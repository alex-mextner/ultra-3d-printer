# nginx на принтере — копии конфигов

Эти файлы **не деплоятся ничем автоматически**. Это снимок того, что реально
лежит на принтере в `/etc/nginx/`, снятый руками, чтобы при переустановке
системы или передаче машины не пришлось восстанавливать раскладку портов по
памяти. Принтер передаётся другому человеку — без этой копии знание жило бы
только в `/etc` на карточке.

Снят 2026-08-19, сразу после обмена портами двух веб-интерфейсов.

## Кто на каком порту

| Порт | Что отдаёт | Каталог на принтере | Файл сайта |
|---|---|---|---|
| **80** | **Форк на Vue 3 (`Mainsail Next`) — основной интерфейс** | `/home/ultra/mainsail-next` | `sites-available/mainsail-next` |
| 8090 | Старый Mainsail (Vue 2) — запасной интерфейс | `/home/ultra/mainsail` | `sites-available/mainsail` |
| 8091 | Репетиционная копия Vue-2-сборки | `/home/ultra/mainsail-stage` | `sites-available/mainsail-stage` |

До 2026-08-19 первые два стояли наоборот: старый Mainsail на 80, форк на 8090.
Поменяли местами по прямой просьбе пользователя.

`sites-available/default` на принтере есть, но **не включён** (симлинка в
`sites-enabled/` нет), поэтому за порт 80 он не спорит. В этой копии его нет
намеренно — он стоковый и к машине отношения не имеет.

## 🔴 Какая копия главная — у каждого файла своя

Это главное, что нужно знать перед правкой, и единственный способ не потерять
изменения при следующем деплое.

- **`sites-available/mainsail-next`** — **главный не здесь.** Файл целиком
  переписывается при каждом запуске `app-next/scripts/deploy-to-printer.sh`
  (ветка `feat/vue3-migration` форка) из heredoc внутри самого скрипта. Правка
  этой копии или файла на принтере будет молча затёрта следующим деплоем.
  Менять — только heredoc в скрипте.
- **`sites-available/mainsail`** — **главный здесь.** Стоковый файл от
  MainsailOS, никакой скрипт его не пишет. `scripts/deploy-to-printer.sh --live`
  из Vue-2-ветки кладёт туда сборку, но порт не трогает. Правится руками на
  принтере, и эта копия обновляется тем же заходом.
- **`sites-available/mainsail-stage`** — как `mainsail-next`: переписывается
  `scripts/deploy-to-printer.sh --stage` из Vue-2-ветки.
- **`conf.d/*.conf`** — общие для всех трёх сайтов и правятся руками.
  `upstreams.conf` объявляет `apiserver` (Moonraker на `127.0.0.1:7125`) и
  `mjpgstreamer1..4`; `common_vars.conf` — map `$connection_upgrade`, без
  которого не поднимется websocket. Оба существуют в одном экземпляре
  специально: адрес Moonraker описан ровно в одном месте на все интерфейсы.

## Почему в файле форка стоит `location = /sw.js { return 404; }`

Не опечатка и не заглушка. Старый Mainsail — PWA, и пока он стоял на порту 80,
он зарегистрировал service worker на **origin** `http://192.168.11.160/`. Origin
— это схема+хост+порт, и регистрация к сборке не привязана: после обмена портами
браузеры, которые раньше открывали старый интерфейс, продолжали бы отдавать его
закешированную оболочку с голого адреса. Отдать `404` на `/sw.js` — единственный
способ заставить браузер снять регистрацию (`200` с HTML, который иначе вернул бы
SPA-fallback, читается как неудачное обновление и регистрацию **сохраняет**).

🔴 Если форк когда-нибудь обзаведётся собственным service worker по этому же
пути — блок убрать, иначе он будет глушить свой же worker. Старому Mainsail на
`:8090` этот блок не мешает: там свой origin и свой законный `/sw.js`.

## Правило про порты

Два файла сайтов **никогда не должны называть один и тот же порт**. Два `server`
на одном порту с `server_name _` — для nginx не ошибка: `nginx -t` пройдёт, и
порт молча достанется тому, чей файл раньше по алфавиту (`mainsail` идёт до
`mainsail-next`). То есть коллизия не падает, а тихо подменяет интерфейс.
Проверять после любой правки портов не кодом ответа, а `<title>`:
`Mainsail Next` — форк, просто `Mainsail` — старый.

## Восстановить на чистой системе

```sh
scp sites-available/* root@192.168.11.160:/etc/nginx/sites-available/
scp conf.d/*          root@192.168.11.160:/etc/nginx/conf.d/
ssh root@192.168.11.160 '
  for s in mainsail mainsail-next mainsail-stage; do
    ln -sfn /etc/nginx/sites-available/$s /etc/nginx/sites-enabled/$s
  done
  nginx -t && systemctl reload nginx'
```

Сами каталоги со сборками (`/home/ultra/mainsail*`) этим не восстанавливаются —
их кладут скрипты деплоя из соответствующих веток форка.
