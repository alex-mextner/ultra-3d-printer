Как поставить сгенерированный профиль принтера в слайсер

klipper_to_orcaslicer.py генерирует профиль принтера прямо из живого конфига Klipper (размер стола, диаметр сопла, скорости/ускорения) и кладёт его на сам принтер, откуда файл можно скачать через Mainsail. Дальше — куда его положить и что переживает установку, а что нет. По слайсерам это сильно отличается, ниже — честно, без «просто скопируйте файл» там, где это неправда.

Формат файлаJSON-профиль печатной машины OrcaSlicer (вендор «Custom»)
Совместимо напрямуюТолько OrcaSlicer
PrusaSlicer / SuperSlicer / CuraДругой формат — файл не подходит, см. ниже
Главное правилоСлайсер нужно полностью перезапустить, не просто переоткрыть проект

Откуда взять файл

На принтере с этим порталом (или любом другом, где развёрнут klipper_to_orcaslicer.py) файл лежит под Moonraker-корнем config и доступен двумя способами из Mainsail:

  • Файловый браузер Mainsail → Config Files → папка со слайсер-профилем.
  • Прямая ссылка-скачивание в сайдбаре Mainsail (если она настроена через .theme/navi.json — см. mainsail-theme/README.md в репозитории этого проекта) — Moonraker отдаёт файл с заголовком Content-Disposition: attachment, то есть браузер сразу предложит сохранить, а не откроет как текст.
Это снимок, не живая связь

Скачанный файл отражает конфиг Klipper на момент генерации. Если конфиг принтера изменился (поменяли сопло, скорости и т.п.) — файл нужно перекачать заново и переустановить в слайсер. Никакой слайсер сейчас не умеет сам «подтягивать» изменения с принтера в реальном времени — это не недоработка конкретно этого инструмента, а ограничение всей экосистемы Klipper/слайсеров на сегодня.

OrcaSlicer — работает напрямую

проверено вживую, не только по документации

Файл — это ровно формат профиля печатной машины OrcaSlicer (вендор Custom), поэтому его достаточно положить в пользовательскую папку профилей и перезапустить приложение.

ОСКуда класть файл
Windows%APPDATA%\OrcaSlicer\user\default\machine\
macOS~/Library/Application Support/OrcaSlicer/user/default/machine/
Linux~/.config/OrcaSlicer/user/default/machine/

default — это папка профиля «без входа в облачную синхронизацию»; если когда-либо логинились в аккаунт OrcaSlicer, вместо default может быть папка с числовым ID — тогда ищите её рядом. Имя самого файла (например ULTRA-mini.json) не обязано совпадать с тем, что покажет OrcaSlicer в списке — имя профиля берётся из поля name внутри файла, не из имени файла на диске.

Перезапуск обязателен

OrcaSlicer читает эту папку только при старте, а не постоянно — простое сохранение проекта или переключение вкладки не подхватит новый/изменённый файл. Перезапустите приложение целиком. Проверено на практике: после перезапуска OrcaSlicer сам пересохраняет файл в своём каноническом виде (переупорядочивает поля, добавляет свои значения по умолчанию для того, что не было указано) — это нормальное поведение и заодно подтверждение, что профиль реально загрузился.

Если профиль наследуется (поле inherits) от базового пресета вроде MyKlipper 0.6 nozzle — такой пресет должен реально существовать среди системных профилей OrcaSlicer (обычно ставится вместе с самим приложением, вендор Custom). Несуществующий родитель — частая причина, почему профиль не подхватывается или подхватывается с пустыми полями.

PrusaSlicer / SuperSlicer — файл НЕ подходит напрямую

несовместимый формат — не пытайтесь просто скопировать

PrusaSlicer и его форк SuperSlicer хранят профили в формате .ini (простой текст «ключ=значение»), а не в JSON, который использует OrcaSlicer. Это не вопрос «переименовать расширение» — структура полей и то, как считаются проценты/абсолютные значения для некоторых настроек, у слайсеров разное. Готового официального конвертера нет; существуют сторонние скрипты сообщества для обратного направления (PrusaSlicer/SuperSlicer → OrcaSlicer), но не для OrcaSlicer → PrusaSlicer, и точность не гарантирована.

Что реально сделать: открыть скачанный JSON-файл текстом (или собрать статус-макросом NOZZLE_STATUS на самом принтере) и руками перенести числа — размер стола, диаметр сопла, максимальные скорости/ускорения — в PrusaSlicer через Printer Settings → General/Custom G-code/Machine limits. Дольше, чем импорт файла, но единственный надёжный путь без стороннего конвертера.

Cura — файл НЕ подходит напрямую

несовместимый формат

Cura описывает машины файлами .def.json собственной схемы (движок Cura, не Slic3r-семейство) — структура полей другая, прямого импорта JSON-профиля OrcaSlicer в Cura нет.

Что реально сделать: завести принтер через мастер Cura Settings → Printer → Add Printer → Add a non-networked printer → Custom, вписав те же числа (стол, сопло, скорости) вручную из скачанного профиля. Как и с PrusaSlicer — не «поставить файл», а один раз перенести значения.
