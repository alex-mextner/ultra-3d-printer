# Задание: доделать printer.cfg и завершить первый запуск (mbot, Klipper)

Это продолжение работы из `~/Downloads/klipper-mbot-запуск.md` (тот файл — общий план запуска, читай его как справочный материал, если нужен контекст по железу/шагам 0-3). Этот файл — конкретное текущее задание: чинить конфиг и довести первый запуск до конца.

## Доступ к принтеру

- Веб-интерфейс (Mainsail/Fluidd): http://192.168.11.160/
- SSH: `ssh root@192.168.11.160` или `ssh ultra@192.168.11.160` (пароль — в `.env`, `PRINTER_SSH_PASSWORD`)
- Конфиг Klipper: `~/printer_data/config/printer.cfg` (стандартный путь KIAUH-установки)
- Локальная сеть, доступ только по Ethernet с Orange Pi One.

## Железо (кратко, подробности в klipper-mbot-запуск.md)

- Хост: Orange Pi One (Armbian), Klipper/Moonraker/Mainsail уже установлены через KIAUH.
- MCU: Freaduino Mega2560 v1.4 (клон Arduino Mega2560) + шилд RAMPS 1.4 с TMC2209 в панельках. Подключён к Orange Pi по USB.
- Пиновка — бери за основу штатный `config/generic-ramps.cfg` из репозитория Klipper (https://github.com/Klipper3d/klipper/blob/master/config/generic-ramps.cfg), это классическая RAMPS+Mega распиновка, руками пины лучше не гадать.
- Есть рулетка — используй для измерения реальных ходов осей (`position_max` по X/Y/Z) и, если нужно, для прикидки геометрии ремня/шкива под `rotation_distance`, если нет точных данных по редуктору.

## Текущий статус физического железа

- Концевики **Z и Y установлены и подключены**.
- Концевик **X пока не подключён физически**. На сегодня это ок — либо настроить его временно программно (например sensorless homing через TMC2209 stallguard на `diag_pin`, если шилд/проводка это позволяет), либо просто не хомить X сегодня и ограничиться ручным джогом/STEPPER_BUZZ, как это уже сделано для проверки. Выбери более простой вариант, не трать много времени на sensorless homing если не пойдёт с первого раза — можно оставить X без хоминга до покупки концевика.
- **Стол (нагревательный, K1 Max + SSR) физически ещё не подключён.** Секцию `[heater_bed]` в конфиг пока НЕ добавлять — Klipper нормально стартует без неё. Всё, что касается 220V/SSR — не в рамках этого задания, отдельная история на будущее.

## Блокирующая ошибка на момент написания этого файла

```
Could not find stepper config section '[extruder]' required by TMC autotuning
```

Диагноз: ошибку кидает не сам Klipper, а сторонний плагин **klipper_tmc_autotune** (andrewmcgr). В конфиге есть секция `[autotune_tmc extruder]` (и возможно похожие `[autotune_tmc stepper_x/y/z]`), а секции `[extruder]` (с реальными пинами мотора/нагревателя), которую эта секция требует, либо нет, либо она неполная/с опечаткой в имени.

**Порядок действий:**

1. Посмотри, что реально есть в конфиге сейчас:
   ```bash
   grep -n "^\[" ~/printer_data/config/printer.cfg
   ```
   Это покажет все секции целиком — сверься, для каждой `[autotune_tmc X]` есть ли соответствующая базовая секция `[X]` с уже заполненными реальными пинами (не `...`-заглушками).

2. Если `[extruder]` (или `[stepper_x/y/z]`) ещё не дописана до конца (пины/`rotation_distance`/`sensor_type` и т.п. — заглушки или отсутствуют) — сначала дописать её по-нормальному, используя `generic-ramps.cfg` как источник пинов. Автотюн TMC требует полностью рабочих базовых секций степперов/экструдера — это не опция, которую можно включить раньше времени.

3. Если по итогу пока не хочется настраивать автотюн (это опционально, TMC2209 и без него прекрасно работает с ручным `run_current`) — просто закомментируй все `[autotune_tmc ...]` секции целиком (каждую строку через `#`) и не включай плагин, пока остальное не заработает. Автотюн — это удобство, а не обязательный компонент.

4. После правки — `FIRMWARE_RESTART` в консоли Mainsail (или `sudo service klipper restart` по SSH), проверить, что Klipper стартует без ошибок.

## Дальше — довести до состояния "первый запуск без стола"

Ориентируйся на шаги 3-6 из `klipper-mbot-запуск.md`, коротко:

1. Прошивка MCU уже должна быть залита (шаг 3 гайда) — если ещё нет, сделать это раньше остального.
2. Для каждого степпера (`stepper_x`, `stepper_y`, `stepper_z`, `extruder`) — реальные пины из `generic-ramps.cfg`, `microsteps: 16`, для степперов X/Y/Z — `rotation_distance` по факту редуктора/шкива (перепроверить, не бездумно копировать `40` из шаблона).
3. `run_current` в `[tmc2209 ...]` секциях — по паспорту моторов (обычно указано на шильдике мотора), если данных нет — начинать с заниженного (`0.4A`) и поднимать по `0.1A`, проверяя нагрев корпуса мотора и отсутствие пропусков шагов. `hold_current` держать заметно ниже `run_current` (например вполовину).
4. После правки конфига: `FIRMWARE_RESTART`, затем по очереди `STEPPER_BUZZ STEPPER=stepper_x` / `stepper_y` / `stepper_z` / `extruder` — мотор должен качнуться на 1мм 10 раз без пропусков и скрежета. Экструдер можно бузить без филамента, это безопасно.
5. Concevики Z и Y — после успешного BUZZ можно аккуратно проверить `QUERY_ENDSTOPS` и ручной джог малыми шагами (`G91` → `G1 Z5 F300` и т.п.) перед тем как пробовать `G28` по этим осям. **X пока не хомить** (см. выше).
6. Нагрев сопла — только под присмотром, см. чеклист безопасности ниже. Не отключай `verify_heater`/thermal runaway защиту. Сверь `sensor_type` с реальным термистором хотэнда (не оставляй "Generic 3950" по умолчанию не проверив).

## Чеклист безопасности перед тестами (из основного гайда)

- [ ] `run_current` выставлен по паспорту моторов, не наугад
- [ ] Направление `dir_pin`/`enable_pin` проверено через `STEPPER_BUZZ`, а не через реальный ход в раму
- [ ] Концевик X не подключён → `G28` по X не запускать (или сделать sensorless homing и явно это проверить перед хомингом)
- [ ] Тип термистора хотэнда соответствует реальному
- [ ] Напряжение нагревателя хотэнда (12V/24V) совпадает с реальным питанием
- [ ] `verify_heater` (thermal runaway) включена, не закомментирована
- [ ] `[heater_bed]` отсутствует в конфиге, пока стол не подключён
- [ ] Первый нагрев сопла — не отходить, следить за графиком температуры в Mainsail первые 10-15 минут
